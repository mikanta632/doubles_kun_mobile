# ダブルスくんモバイル

ダブルスの組み合わせをその場で作るアプリのブラウザ版。スマホのホーム画面に追加して使う。

**公開先**: https://mikanta632.github.io/doubles_kun_mobile/

デスクトップ版（PySide6）の中核ロジックを TypeScript に移植したもの。組み合わせエンジン、
一括計画（焼きなまし）、Elo、一日の指標、ペア強度モデルの推定はデスクトップ版と同じ結果を出す。
`tests/golden/` にデスクトップ版が書き出した正解データがあり、乱数の消費順まで揃えて
一致を確認している（`tools/make_golden.py`）。
ただし v0.13.0 から、試合タブの「次の試合を組む」は連続ラウンドの回避（エンジンの `avoidConsecutive`、デスクトップ版にない）を
有効にして使っている。正解データとの一致を確かめているのは、これを無効にしたときの結果。

## 使い方

1. 試合タブの見出し（プロジェクト名）をタップして「新しく作る」。名前・日付・場所を入れ、参加するメンバーをデータベースから選ぶ
   （いまのプロジェクトと同じメンバーにもできる。データベースにいない人はその場で登録できる）。
   あとからのメンバーの追加・削除も、見出し →「編集」→「メンバー」で行う
2. メンバーは全員、組み合わせに入る。その場にいるが組み合わせから外す人（休憩・けがなど）だけ、メンバータブでチェックを外す
3. 試合タブの「次の試合を組む」で案を見て、待機に加える（右上のボタンで何試合ぶんかをまとめて組むこともできる）。
   待機の試合は決まった試合として出場回数・同席・ラウンドに数える。試合中の人は案に入らない
   （待機が面数ぶん以上あり、その試合が 2 ラウンド以上前なら、その頃には終わっているので入る）。
   前のラウンドに出た人（待機の試合も含む）は、なるべく続けて入れない（「まとめて組む」は従来どおりで、この回避はしない）
4. コートに入ったら待機の試合の「開始」で進行中にし、終わったら「結果」でスコアを入れる（終了に移る）。
   待機と終了は長押しして動かすと順番を入れ替えられる。試合をタップすると詳細（勝率予想・4 人のレートと出場回数・結果）が見られ、
   そこから開始・結果の入力・削除ができる。見出しの「選ぶ」で何試合かを選んでまとめて削除できる
5. 集計タブで、成績や出場回数・待ちの偏りを確認する（そのプロジェクトのメンバーだけが対象。組み合わせから外した人も入る）

メンバーは 3 層になっている。データベース（端末に登録した全員）→ プロジェクトのメンバー（参加者）→ 組み合わせに入れる人。
プロジェクトに参加していない人は、そのプロジェクトでは集計にも組み合わせにも出てこない。
プロジェクトは複数作れて、試合タブの見出しから切り替える。メンバー・試合・設定はプロジェクトごと、データベースは共通（設定タブの「メンバーのデータベース」で編集する）。

データベース（設定タブ →「メンバーのデータベース」）でできること:

- 登録・編集・削除。名前・所属・レート順の並べ替えと、所属での絞り込み
- 「選んでまとめて操作」で、何人かをまとめて所属を変える・休会にする・削除する
- データベースはプロジェクトから独立している。ここで登録してもプロジェクトのメンバーには入らない（メンバーはプロジェクトの作成・編集で選ぶ）
- CSV（Excel で開ける）と JSON での書き出し。読み込むと同じ名前の人は上書きし、新しい人は登録する（プロジェクトのメンバーは変えない）。
  CSV は 1 行目に見出しが必要で、`名前`（または `name`）の列は必須。`所属`・`レート`・`休会` は任意で、無い列は登録済みの値を残す（`初期レート` の列も読めて、`レート` がなければそれを使う）。
  UTF-8 と Shift_JIS のどちらでも読める
- 名前をタップすると、その人が出たプロジェクトごとの試合数と勝敗が見られる

データベースの人（名前・所属・レート・休会）を変えたり消したりできるのは、この画面だけ。
メンバータブで名前をタップすると、記録の確認と「遅れて来た」の設定ができる（データベースの人は変えない）。

設定タブの「表示 → レートを隠す」を入れると、レートと勝率予想を画面に出さない（全プロジェクト共通）。
組み方や書き出しにはそのままレートを使う。隠している間は、データベースで登録した人のレートは 1500 になる。

レートは 1 人 1 つの固定値で、試合結果では動かさない（Elo での自動更新はいまは使わない）。直すときはデータベースで手で直す。
保存データの rating と initial_rating はいつも同じ値にしてある（デスクトップ版のファイル形式との互換のため 2 つ残している）。
v0.10.0 より前のデータで 2 つが違っていた人は、一覧に出ていた rating にそろえ、初期レートは控えに残した（試合の一覧の「元に戻す」で初期レートの方にそろえ直せる）。

設定タブの「データ → 試合の一覧」に全プロジェクトの試合が並ぶ。ここから「試合結果から p を推定」（全プロジェクトの試合から推定し、
開いているプロジェクトの p に入れる）ができ、「元に戻す」で推定前の p に戻せる。

遅れて来た人は、メンバータブで名前をタップして「遅れて来た人にする」。仮の試合数（実際の出場に足す）を決めておくと、
ほかの人に追いつこうとしてその人ばかり入るのを避けられる。連続待ちは来た時点から数え、まだ誰とも同席していない分は
ほかの人どうしの平均の同席回数を仮に持たせる（同席回数は出場回数の公平さより優先して見るので、これがないと新しく来た人が選ばれ続ける）。

データはブラウザの中にだけ保存される。設定タブから JSON で書き出せる。
`players.json`（メンバー）と `matches.json` はデスクトップ版のプロジェクトフォルダにそのまま置ける。

## 開発

```bash
npm install
npm run dev      # 開発サーバー
npm test         # 正解データとの突き合わせ
npm run build    # dist/ に出力
```

正解データを作り直すときは、デスクトップ版のリポジトリを隣に置いて

```bash
npm run golden
```

`main` に push すると GitHub Actions が GitHub Pages に配信する。
